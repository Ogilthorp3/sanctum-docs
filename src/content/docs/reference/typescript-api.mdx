The TypeScript config module at `command-center/lib/config.ts` provides typed access to the Sanctum instance configuration. It reads from the same `~/.sanctum/instance.yaml` file as the shell library and is used by the command center dashboard and any Node.js tooling.

Same YAML. Same config. Same haus. But now with type safety, because if your haus is going to be managed by code, that code should at least know the difference between a string and a number. The shell library makes no such promises.

```typescript
import {
  get,
  getConfig,
  isEnabled,
  expand,
  slug,
  name,
```

That's twenty-one named exports for reading config about a haus. There was a time when hauses just had a thermostat and a doorbell. We've come so far. Whether the direction is forward is left as an exercise for the reader.
</Aside>

## Config Access

### get()

Read any value from the instance config by dot-notation path. The optional
second argument is the fallback returned when the path is missing — so `get`
hands you a `T`, never an `undefined` you forgot to guard.

```typescript
function get<T = string>(path: string, fallback?: T): T
```

| Parameter | Type | Description |
|-----------|------|-------------|
| `path` | `string` | Dot-delimited path into the config |
| `fallback` | `T` | Value returned if the path is absent (default `undefined`) |

```typescript
const port = get('services.dashboard.port', 3001);
// 3333

const vmIp = get('network.vm_ip');
// "10.0.0.10"

const tz = get('instance.timezone');
// "America/New_York"
```

---

### getConfig()

Return the entire parsed configuration object. The whole thing. Every detail your haus knows about itself, in one typed object.

```typescript
function getConfig(): SanctumConfig
```

```typescript
const config = getConfig();
console.log(config.instance.name);
// "Manoir Neo"
```

---

### isEnabled()

Check whether `services.<name>.enabled` is `true`. You pass the bare service
name — `isEnabled` prefixes the `services.` and suffixes the `.enabled` for
you. Pass the full path and it goes looking for `services.services.x.enabled`,
finds nothing, and politely returns `false`.

```typescript
function isEnabled(service: string): boolean
```

```typescript
if (isEnabled('signal_proxy')) {
  console.log('Signal bridge proxy is active');
}

if (isEnabled('voice_agent')) {
  // ...
}
```

---

### expand()

Expand a leading `~` to the configured Mac home directory (`users.mac.home`).
Just the tilde — no `{{token}}` interpolation, no environment substitution.
It is the smallest possible path helper, and it knows it. Anything that
doesn't start with `~` comes back untouched.

```typescript
function expand(path: string): string
```

```typescript
const result = expand('~/Projects/openclaw-skills');
// "/Users/neo/Projects/openclaw-skills"
```

### vmSsh()

Return the VM SSH target as `user@ip`, assembled from `users.vm.username` and
`network.vm_ip`. Not an SSH-config alias — the literal address you can hand to
`ssh`.

```typescript
function vmSsh(): string
```

```typescript

// "ubuntu@10.0.0.10"
```

### whoami()

Return the current node identity (read from `~/.sanctum/.node_id`).

```typescript
function whoami(): string
```

```typescript
whoami();
// "manoir"
```

---

### isNode()

Check if the current machine matches a given node ID — a string compare against
`whoami()`. Note it takes a node *ID* (`manoir`), not a node *type* (`hub`); the
two are easy to confuse, and the type system won't save you here.

```typescript
function isNode(nodeId: string): boolean
```

```typescript
if (isNode('manoir')) {
  console.log('Running on the manoir hub');
}
```

---

### myNodeType()

Return the node type of the current machine — reads `nodes.<whoami>.type`.

```typescript
function myNodeType(): string
```

```typescript
myNodeType();
// "hub"
```

A plain `string`, not a sealed union. The convention is `hub`, `satellite`,
`mobile`, or `sensor` — the kinds of places your haus exists — but the function
returns whatever the YAML says. The type system doesn't judge. It just relays.

## Node Topology

### nodeGet()

Read a field for a specific node — sugar for `get('nodes.<id>.<field>')`, with
the same optional fallback.

```typescript
function nodeGet<T = string>(nodeId: string, field: string, fallback?: T): T
```

| Parameter | Type | Description |
|-----------|------|-------------|
| `nodeId` | `string` | Node identifier (e.g., `"manoir"`, `"chalet"`) |
| `field` | `string` | Dot-delimited path within that node's config |
| `fallback` | `T` | Value returned if the field is absent |

```typescript
nodeGet('manoir', 'tailscale_ip');
// "100.0.0.20"

nodeGet('chalet', 'type');
// "satellite"

nodeGet('manoir', 'host');
// "192.0.2.10"
```

---

### getNodes()

Return the full nodes dict, keyed by node ID. For just the IDs, take the keys.

```typescript
function getNodes(): Record<string, Record<string, unknown>>
```

```typescript
Object.keys(getNodes());
// ["manoir", "chalet", "mbp", "ruview_front",
//  "ruview_basement", "ruview_garage", "ruview_living"]
```

---

### getNodesByType()

Return nodes filtered by type, each as its full config object with the `id`
folded back in.

```typescript
function getNodesByType(type: string): Array<{ id: string } & Record<string, unknown>>
```

```typescript
getNodesByType('hub');
// [{ id: "manoir", type: "hub", display_name: "Manoir Neo", ... }]

getNodesByType('satellite').map((n) => n.id);
// ["chalet"]
```

---

### getSatellites()

Convenience wrapper for `getNodesByType('satellite')` — all satellite nodes as
config objects.

```typescript
function getSatellites(): Array<{ id: string } & Record<string, unknown>>
```

```typescript
getSatellites().map((n) => n.id);
// ["chalet"]
```

---

### nodeHub()

Return the hub node ID that a given satellite syncs with — reads
`nodes.<id>.sync.hub`. It answers "who does this satellite report home to,"
not "which node is the hub." Subtle difference, load-bearing in a two-haus
topology.

```typescript
function nodeHub(nodeId: string): string
```

```typescript
nodeHub('chalet');
// "manoir"
```

---

### isNodeOnline()

Read the static `nodes.<id>.online` flag from config. Synchronous, no Promise,
no network — it reports what the YAML last declared, not what the wire is doing
right now.

```typescript
function isNodeOnline(nodeId: string): boolean
```

```typescript
if (isNodeOnline('chalet')) {
  console.log('Chalet is marked online');
}
```

<Aside type="caution">
"Online" here means a boolean in a file, not a live probe. If the chalet's power
went out an hour ago, this still cheerfully says `true` — the YAML hasn't heard
the news. Trust it for topology, not for liveness; reach for an actual ping when
you need the truth about the cabin in the woods.
</Aside>

## Dashboard Integration

The command center dashboard serves the instance config (with secrets excluded) at the `/api/config` endpoint:

```typescript
// server/index.ts
import { getConfig } from '../lib/config.js';

app.get('/api/config', (_req, res) => {
  const cfg = getConfig();
  // Serve everything except secrets
  const { secrets: _s, ...safe } = cfg;
  res.json(safe);
});
```

`vite.config.ts` reads its dev-server port (and the proxy targets) from the
config module rather than hardcoding them — so the dashboard listens where
`instance.yaml` says, with a sane default if the key is missing:

```typescript
// vite.config.ts
import { get } from './lib/config.js';

const dashboardPort = get('services.dashboard.port', 3001);
// ...
server: { port: dashboardPort };
```

<Aside type="tip">
That second argument to `get` — the `3001` fallback — is the real belt-and-suspenders
here: the dashboard still boots even if someone fat-fingers the port out of the YAML.
Every `get()` on this page carries the same quiet insurance. A config file that runs
your haus should fail soft, not dark.
</Aside>
