When your haus talks to the cloud, it should not just ask for an API key and hope. The original `sanctum-cloud-proxy` was a ~100-line Python script that did the security checks by hand — fetching keys, tracking spend, managing fallbacks. It worked. But it chained the Python interpreter to our most critical networking path, and every autonomous action waited on an interpreter start.

So we folded the whole hardening suite into the existing `sanctum-proxy` Rust crate. The Python proxy is gone. The native daemon does it all — `proxyd`, launchd label `com.sanctum.proxyd`.

## How It Works

`proxyd` binds `0.0.0.0:4040`. That is all interfaces, so it answers on both `127.0.0.1` and the `10.10.10.1` Mac↔VM bridge. It intercepts every LLM API request and runs it through five layers of verification before forwarding to the cloud — Anthropic, OpenRouter, Gemini — or routing it to a local MLX seat.

## The Five Layers of Hardening

<Steps>
1. **Key Security** — No API key lives in source, a `.env` file, or Git. At runtime `keychain.rs` reads `<PROVIDER>_API_KEY` from the environment first; the launchd wrapper `proxyd-launch` injects `GEMINI_API_KEY` and `OPENROUTER_API_KEY` from `~/.sanctum/secrets/`. Miss that, and it falls back to the macOS login [keychain](/architecture/secrets-trifecta/) via the `security-framework` crate (`service=<provider>-api-key, account=sanctum`). A daemon must never block on a consent dialog. So a missing key **fails closed**: it logs once, returns empty, and lets the request emit a clean auth error — no AppleScript prompt in the operator's session at 3 a.m.
2. **Fallback Chain** — A provider returns a 429, a 5xx, or a timeout. `proxyd` walks a per-model [fallback chain](/architecture/fallback-continuity/) — the `fallbacks:` map in `config.yaml` — until something healthy answers, and the client never learns a hop failed. The chain bottoms out on local MLX seats: the `Devstral-Small-2-24B-Instruct-2512-4bit` coder on `:3301` and the cathedral council seat (`qwen3.6-35b-a3b-4bit`) on `:1337` mTLS. The cloud can be on fire. Your `git commit` message still gets written. **Subscription-first routing:** the Claude-backed seats — `council-brain` (Jocasta and Mon Mothma) and `council-max-thinking` (Yoda and Mundi) — lead with the best subscription Opus, `claude-opus-4`, served as Opus 4.8 through the Claude Max bridge on `:3456`. They fall back to the cathedral, never to metered OpenRouter. That rule was earned. An earlier chain spilled those seats to OpenRouter when Opus throttled under load; with the balance dry, that surfaced as `402` seat dropouts, so their fallbacks were rerouted to local-only — `council-mlx`, then the Devstral lane.
3. **Cost Control (Daily Caps)** — The proxy tracks real-time USD spend in memory. Per-agent [daily caps](/architecture/proxyd-budget/) are baked into `budget.rs`: `windu=$2.00`, `mothma=$2.00`, `jocasta=$1.50`, everyone else `$0.50`. Blow the cap and cloud routes silently drop off your menu, folding you onto local inference. The agent that overspends doesn't get an error. It gets a quieter model.
4. **Audit Trail & Observability** — Every request appends a structured line to `~/.sanctum/logs/cloud-proxy-audit.jsonl` — agent, model, tokens, cost, latency, running daily total. The `/stats` endpoint on `:4040` serves the live tally as JSON. "Who spent what today" is one `curl` away, not a `grep` through logs.
5. **Provider Health Gating** — There is no global rate limiter. What `proxyd` keeps instead is a sliding-window health score per provider, in `budget.rs` — `ProviderHealth`: success rate plus average latency, aged by exponential decay. Cross 30% errors and a provider is marked unhealthy and skipped for the next link in the chain — routing around a flaky upstream instead of hammering it.
</Steps>

<Aside type="caution" title="No token bucket here">
An earlier draft called Layer 5 "a token bucket with exponential backoff." It isn't. The only thing in the binary by that name is the per-agent USD budget in Layer 3, and the only "backoff" is a 250 ms socket-bind retry at startup. The doc now says what the code does: health gating, not rate limiting.
</Aside>

## Why Rust?

LLM routing sits on the critical path for every autonomous action in the Sanctum. The Python implementation added measurable latency on every hop — HTTP parsing, interpreter context switches, the `requests` import tax. Folding the hardening logic into the `sanctum-proxy` binary paid off three ways. We dropped the Python interpreter and the `requests` library entirely, so the resident set now sits in the low tens of MB instead of the Python baseline. Concurrency improved sharply under the `tokio` async runtime; SSE streams from many agents share one process without thread-per-request bloat. And smart intent routing and security hardening now live in one repo, `sanctum-rs`, instead of straddling two languages.

## Configuration & Dynamic Healing

`proxyd` loads its initial settings from `~/.sanctum/sanctum-proxy/config.yaml`. The config is live, though, not load-once. Edits are caught by the `notify` crate's filesystem watcher and swapped into memory via `arc-swap`, so a new fallback chain or model entry takes effect without dropping an in-flight SSE stream. You retune routing without bouncing the daemon — and without the agent mid-essay noticing. The proxy also refuses to trust the agent about its own model. It resolves identity from headers or endpoint routing and meters the *actual* tokens the upstream returned. An agent that asks for a cheap model to dodge its cap still gets billed for what it really burned.

## Post-Quantum Transport

The `:4040` front door is born post-quantum. Every TLS handshake negotiates the hybrid **X25519MLKEM768** key exchange — classical X25519 plus ML-KEM-768. An adversary recording today's traffic to decrypt once a quantum computer arrives harvests nothing usable. The inner `proxyd`-to-cathedral hop on `:1337` enforces the same group, with no classical fallback. Confirm it on the wire with `~/.sanctum/scripts/pqc-status.sh`. It asserts the negotiated group per hop and refuses to run on a LibreSSL stack that would lie green.

The signature half is a different story. Migrating cert trust from classical ECDSA-P256 to **ML-DSA-65** (FIPS 204) is prepared and proven — not yet cut over. The `rustls-post-quantum` provider swaps are committed on feature branches, with KEX preservation re-asserted so the swap cannot silently downgrade. The staging ML-DSA-65 PKI verifies. The gateway's real stack — Node 22 on OpenSSL 3.5.5 — was confirmed to verify an ML-DSA chain end to end. The live cutover waits behind a council-set checklist in `~/.sanctum/runbooks/PQC-PHASE4-STATUS-2026-06-18.md`. The reasoning is deliberate. The key-exchange hedge already closed the only harvest-now exposure. Signatures defend against a live quantum man-in-the-middle — a threat with no present actor — so they ship on purpose, not in a hurry.
