The Mac Mini is box-fresh on your desk. Default wallpaper, zero apps, an innocent little aluminum puck with no idea it's about to inherit the workload of a small municipality. You have a hot mug of tea and roughly one period of hockey before somebody in the haus yells your name. Thirty minutes from now, that puck is *alive* — running a 27-billion-parameter brain locally, backing up your life nightly, and phoning home to exactly nobody. No static IP. No domain. No SaaS ransom note. (If you want the director's cut with all the edge cases, see [Installation](./installation/). This is the speedrun we hand beta testers.) Tea's still hot. Maximum effort. Let's roll.

## Before you start

Sanctum's first install runs on an **Apple Silicon Mac with 32 GB of memory**. A Mac Studio and a Mac Mini are the same install. 32 GB is the line because the local model, the Dragon, is a 27-billion-parameter model and it fills the machine. A 16 GB Mac can still install the backup tools. It cannot hold the Dragon. The shopping list is on [Requirements](./requirements/).

You also need:

- A free [Cloudflare account](https://dash.cloudflare.com/sign-up) (the R2 free tier — 10 GB — is what we'll use for backups).
- A spare half-hour. Bring tea.

You do **not** need:

- A static IP. Sanctum runs entirely on your LAN with no inbound ports.
- A separate domain name. The internal certificates are minted locally.
- Apple Developer credentials. Everything in the quick path uses Homebrew + Python.
- A subscription to anything. There's no cloud login for Sanctum itself.

## The path

<Steps>

1. **Run the Sanctum bootstrap installer** (installs Homebrew if missing, `sanctum-cli` + `restic`, and the signed Node.js Foundation `.pkg`).

   ```bash
   curl -fsSL https://sanctum.run/install.sh | bash
   ```

   Prefer to eyeball and verify the SHA-256 hash first, or install directly via Homebrew? Use the [verified 2-step path](./installation-family-pass/) or run:

   ```bash
   brew install ogilthorp3/sanctum/sanctum-cli
   ```

   Homebrew installs into `/opt/homebrew/` and asks for your password once. On Homebrew 5.x, inspect the formula and accept the one-time third-party tap prompt with `brew trust --formula ogilthorp3/sanctum/sanctum-cli`.

2. **Confirm `sanctum` is on your PATH.**

   ```bash
   sanctum --version
   sanctum --help
   ```

   Seeing `status`, `doctor`, `onboard`, `backup`, and `chat` means you are ready.

   <Aside type="tip">
   A brand-new Mac may prompt for Apple's Command Line Tools. Let Apple finish, then re-run the installer — it is idempotent.
   </Aside>

3. **Run onboarding.**

   This is the moment.

   ```bash
   sanctum onboard --recipe family
   ```

   An ASCII splash greets you by name, followed by five chapters — **Welcome → Your AI → Your Network → Your Data → You're Alive** — where green checks light only when a step genuinely clears:

   - **Your AI** wires up **Claude** (Max/Pro subscription or API key) and **Gemini** (Google AI key) into macOS Keychain. Skip both if you only want the local Dragon; cloud seats are optional.
   - **Your Network** probes for a Bell hub, Firewalla, and Orbi. Skip it on a friend's desk — that rack lives at the operator's haus.
   - **Your Data** sizes your backup set (Documents, Desktop, ssh keys, dotfiles), walks Cloudflare R2 setup, previews a dry run, runs the backup, and restores a canary file to prove the round-trip.

   When it finishes, a green panel announces **"Your Sanctum is alive, &lt;your name&gt;."** Take a screenshot.

4. **Install the full signed Rust Sanctum engine (`sanctum-rs`) + `dragon-2` champion.**

   One command verifies SHA-256, deploys all **32 Apple Developer-ID signed Apple Silicon Rust binaries + `mlx.metallib` + ablation vectors** (`sanctum-mlx`, `proxyd :4040`, `sanctum-presidio`, `sanctum-memory`, `castellan`, `sanctum-force-flow`, `sanctumd`, `sanctum-msg-bus`, `sanctum-chitti`, `sanctum-thalamus`, `sanctum-triage`, `sanctum-pressure-valve`, `sanctum-chi`, `memory-vault-mcp`, `sanctum-vault`), mints unique per-machine mTLS certs + Keychain proxy key, downloads the **27B Dragon + Jedi-Trials-verified R1 champion LoRA (`193d2d7407ec`)** on 32 GB+ Macs (**+ 9B Coder cathedral on `:3301` for 64 GB+ Macs**, or `Qwen3.5-9B-4bit` on 16 GB), and bootstraps up to 16 auto-starting LaunchAgents (including Memory Vault, Endocrine, and R2D2 heartbeat):

   ```bash
   sanctum haus install
   sanctum haus status
   sanctum council        # opens the full Jedi Council over local Rust proxyd + sanctum-mlx
   ```

   First launch downloads ~15 GB (~5.5 GB on 9B) directly from HuggingFace. *(Prefer the standalone Python venv instead? Run `sanctum dragon install --runtime python`.)*

5. **Connect Yoda on Signal (optional, recommended).**

   The guided installer pulls the latest `signal-cli`, `openclaw`, and `@openclaw/signal`, walks you through pairing a dedicated Signal bot number (QR link or SMS), and wires Yoda directly into your local **Rust `proxyd` (`https://127.0.0.1:4040/v1`) → `sanctum-presidio` → `sanctum-mlx` mTLS `:1337`**:

   ```bash
   sanctum yoda setup
   ```

   <Aside type="note" title="Why a separate bot number?">
     Signal ignores self-messages as loop protection if a bot runs on your personal phone number. Using a dedicated prepaid/eSIM bot number avoids loop protection and keeps your personal Signal account untouched.
   </Aside>

6. **Verify — and keep every component on latest with one command.**

   ```bash
   sanctum status        # the whole haus at a glance
   sanctum haus status   # live health of all Rust daemons
   sanctum doctor        # deep health check
   sanctum update        # updates CLI + Rust sanctum-rs suite + Dragon + Yoda/Signal
   ```

   Expect green across the board. Anything yellow or red tells you exactly what to fix.

7. **Open the studio bundle, if you were handed one.**

   Unzip and run `./install.sh`, then `./yoda.sh hello` so the Mac speaks. `./council.sh` addresses Windu, Qui-Gon, Cilghal, Mundi, or Mothma on that same Dragon; `./r2d2.sh` logs a health line; `sanctum-crm status` opens an empty relationship memory; screen time ships as a template for your own devices. Run `./ha-connect.sh`, `./rest.sh`, then `./holocron.sh` for the Holocron on your Home Assistant. Nothing joins the operator's Signal or LAN.

</Steps>

## What you just got

- **Daily backups**, automatically, via a `haus.sanctum.backup` LaunchAgent that runs at a quiet hour, plus a `haus.sanctum.backup-canary` companion that restores a known file and confirms the round-trip. The backup you can't restore isn't a backup, so we check.
- **A health check you can run anytime** — `sanctum doctor` probes the LaunchAgents, providers, and backup repos; `sanctum self-test` runs the canonical probes that decide whether the install is sound. That's the quick path in a nutshell: a backup, and the means to prove it works.
- **The Dragon**, a local Qwen3.8 27B chat that stays on this Mac. In the studio bundle the council is six names on that one Dragon, and the Mac speaks Yoda. It is not a second model, and it is not the operator's haus.
- **A clean audit trail** — every action that matters is logged to `~/.sanctum/logs/` with bounded rotation. You can read what your haus has been doing, and it won't quietly eat your disk.
- **No phone-home.** Nothing leaves your machine unless you explicitly configure a cloud target (which you just did, for backups, encrypted with a key only you hold).

<Aside type="tip">
If the quick path stalls well past the thirty-minute mark, that is a real bug — not just your tea going cold. File it so we can fix it.
</Aside>

## What to expect over the first week

<CardGrid>
  <Card title="Day 1" icon="rocket">
    You'll get a notification when the daily backup completes. That's intentional. After that, Sanctum will go quiet for a while — it doesn't have anything to tell you yet.
  </Card>
  <Card title="Day 2-3" icon="laptop">
    Talk to the Dragon with `./chat.sh`, or `./yoda.sh` if you have the studio bundle. Try `sanctum status` first thing each morning. Sanctum is meant to fade into the background; if you find yourself running these commands less, that's a sign it's working.
  </Card>
  <Card title="Day 4-7" icon="moon">
    The backup and its canary keep running on their own schedule; you don't tend them. If your Mac reboots for any reason (Apple update, power blip, you walked into the cord), the LaunchAgents come back by themselves — no login, no manual unlock — and pick up where they left off.
  </Card>
  <Card title="When something interesting happens" icon="approve-check-circle">
    A notification that isn't the daily backup means something needs your eyes. Open `sanctum doctor` and read the report. It would rather tell you the awkward truth than show you a reassuring green it can't back up.
  </Card>
</CardGrid>

## When something goes wrong

Sanctum tells you when something's broken — even when it can't fix it yet.

- **`sanctum doctor` is the first stop.** It checks the same things the daily sentinels check, but on demand.
- **The audit log** at `~/.sanctum/logs/r2d2-audit.jsonl` is the second stop. Each cycle carries a `cycle_id`; grep it to follow one run end to end.
- **[Troubleshooting](./troubleshooting/)** has the top issues with copy-paste fixes.
- **Bug reports**: [open an issue on Ogilthorp3/sanctum-cli](https://github.com/Ogilthorp3/sanctum-cli/issues/new/choose). The bug-report template asks for `sanctum doctor` + `sanctum self-test` output and a credentials-redacted checkbox. The maintainers read it.

That is the entire contract, and we didn't even hide it behind a forty-page EULA: your haus will never lie to spare your feelings. A green light it cannot prove is theater, and Sanctum would rather slap an awkward red truth onto your screen than smile while your backups rot. Fix the one red line, refill the mug, and enjoy the eerie silence of infrastructure that actually listens.
