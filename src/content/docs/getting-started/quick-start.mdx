The Mac Mini is box-fresh on your desk. Untouched wallpaper, zero apps, the little aluminum puck just humming there, lowkey waiting for you to give it a job. You've got a hot cup of tea and roughly one hockey period before someone in the haus needs you. Here's the play. Thirty minutes from now, a thing is *alive* on that puck — running on your hardware, watching over the stuff you care about, backing itself up nightly, and phoning home to straight up nobody. No static IP. No domain. No cloud login. The detailed [Installation](./installation/) page goes deeper into the why and the edge cases; this is the friendly path — the one we hand the first beta testers. Tea's still hot. Let's go.

## Before you start

Sanctum's first install runs on an **Apple Silicon Mac with 32 GB of memory**. A Mac Studio and a Mac Mini are the same install. 32 GB is the line because the local model, the Dragon, is a 27-billion-parameter model and it fills the machine. A 16 GB Mac can still install the backup tools. It cannot hold the Dragon. The shopping list is on [Requirements](./requirements/).

You also need:

- A free [Cloudflare account](https://dash.cloudflare.com/sign-up) (the R2 free tier — 10 GB — is what we'll use for backups).
- A spare half-hour. Bring tea.

You do **not** need:

- A static IP. Sanctum runs entirely on your LAN with no inbound ports.
- A separate domain name. The internal certificates are minted locally.
- Apple Developer credentials. Everything in the quick path uses Homebrew + Python.
- A subscription to anything. There's no cloud login for Sanctum itself.

## The path

<Steps>

1. **Install Homebrew** if you don't already have it.

   ```bash
   /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
   ```

   This installs `brew` into `/opt/homebrew/`. It will ask for your password once. That's fine — it needs to write to `/opt/`.

2. **Install sanctum-cli via the Homebrew tap.**

   ```bash
   brew install ogilthorp3/sanctum/sanctum-cli
   ```

   That one command installs Python 3.12 if you need it, then the `sanctum` command.

   Recent Homebrew (5.x) gates third-party taps behind a one-time trust prompt. If you see one, it's asking permission to run our formula — read it, then accept:

   ```bash
   brew trust --formula ogilthorp3/sanctum/sanctum-cli
   ```

   Confirm with:

   ```bash
   sanctum --help
   ```

   A help screen with sub-commands (`status`, `doctor`, `onboard`, `backup`, `chat`) means you're ready.

   <Aside type="tip">
   A first-time Mac may also ask for Apple's Command Line Tools. Let that finish, then come back.
   </Aside>

3. **Run onboarding.**

   This is the moment.

   ```bash
   sanctum onboard --recipe family
   ```

   You'll see a small ASCII splash, then a line that greets you by name, then a guided arc of named chapters — **Welcome → Your AI → Your Network → Your Data → You're Alive** — with a step counter and a green check that lights only when a step genuinely succeeded:

   - **Your AI** connects **Claude** (a Claude Max or Pro subscription, or an Anthropic API key) and **Gemini** (a Google AI key). Keys land in the macOS Keychain. Skip both if you only want the Dragon. The cloud seats are optional.
   - **Your Network** looks for a Bell hub, a Firewalla, and an Orbi. Skip this chapter. Those live on the operator's haus, not on a friend's desk.
   - **Your Data** estimates the backup set (Documents, Desktop, ssh keys, dotfiles), walks Cloudflare R2 setup if needed (auto-opening the right tabs), shows a dry run, runs the real backup, and restores a known file as a canary to confirm the round-trip.

   When it finishes, a recap card and a green panel say **"Your Sanctum is alive, &lt;your name&gt;."** Take a screenshot.

4. **Install the Dragon and talk to it.**

   Quit browsers and other large apps first. The model takes most of a 32 GB Mac.

   ```bash
   curl -fL -o sanctum-dragon.zip \
     https://github.com/Ogilthorp3/homebrew-sanctum/releases/download/dragon-1/sanctum-dragon-guest.zip
   unzip sanctum-dragon.zip
   cd sanctum-dragon-guest
   ./install.sh
   ./chat.sh
   ```

   The first launch downloads about 15 GB. `q` quits. `r` starts over. If you were handed the studio bundle, skip this zip. The bundle already contains the Dragon. `sanctum chat` on a fresh Mac is the operator council, and it bows out.

5. **Verify.**

   ```bash
   sanctum status        # the whole haus at a glance
   sanctum doctor        # deep health check
   ```

   You should see green across the board. If anything is yellow or red, `sanctum doctor` will tell you what to fix.

6. **Open the studio bundle, if the operator handed you one.**

   Unzip it and run `./install.sh`, then `./yoda.sh hello`. The Mac speaks. `./council.sh` asks Windu, Qui-Gon, Cilghal, Mundi, or Mothma, on that same Dragon. `./r2d2.sh` writes a health line. `sanctum-crm status` is an empty relationship memory. Screen time starts as a template you fill with your own devices. `./ha-connect.sh`, then `./rest.sh`, then `./holocron.sh`, opens the Holocron on your Home Assistant. The bundle does not join the operator's Signal or network.

</Steps>

## What you just got

- **Daily backups**, automatically, via a `com.sanctum.backup` LaunchAgent that runs at a quiet hour, plus a `com.sanctum.backup-canary` companion that restores a known file and confirms the round-trip. The backup you can't restore isn't a backup, so we check.
- **A health check you can run anytime** — `sanctum doctor` probes the LaunchAgents, providers, and backup repos; `sanctum self-test` runs the twelve probes that decide whether the install is sound. That's the quick path in a nutshell: a backup, and the means to prove it works.
- **The Dragon**, a local Qwen3.8 27B chat that stays on this Mac. In the studio bundle the council is six names on that one Dragon, and the Mac speaks Yoda. It is not a second model, and it is not the operator's haus.
- **A clean audit trail** — every action that matters is logged to `~/.sanctum/logs/` with bounded rotation. You can read what your haus has been doing, and it won't quietly eat your disk.
- **No phone-home.** Nothing leaves your machine unless you explicitly configure a cloud target (which you just did, for backups, encrypted with a key only you hold).

<Aside type="tip">
If something in the quick path stalls way past the thirty-minute mark, that's a real bug — not your tea going cold. Please report it.
</Aside>

## What to expect over the first week

<CardGrid>
  <Card title="Day 1" icon="rocket">
    You'll get a notification when the daily backup completes. That's intentional. After that, Sanctum will go quiet for a while — it doesn't have anything to tell you yet.
  </Card>
  <Card title="Day 2-3" icon="laptop">
    Talk to the Dragon with `./chat.sh`, or `./yoda.sh` if you have the studio bundle. Try `sanctum status` first thing each morning. Sanctum is meant to fade into the background; if you find yourself running these commands less, that's a sign it's working.
  </Card>
  <Card title="Day 4-7" icon="moon">
    The backup and its canary keep running on their own schedule; you don't tend them. If your Mac reboots for any reason (Apple update, power blip, you walked into the cord), the LaunchAgents come back by themselves — no login, no manual unlock — and pick up where they left off.
  </Card>
  <Card title="When something interesting happens" icon="approve-check-circle">
    A notification that isn't the daily backup means something needs your eyes. Open `sanctum doctor` and read the report. It would rather tell you the awkward truth than show you a reassuring green it can't back up.
  </Card>
</CardGrid>

## When something goes wrong

Sanctum tells you when something's broken — even when it can't fix it yet.

- **`sanctum doctor` is the first stop.** It checks the same things the daily sentinels check, but on demand.
- **The audit log** at `~/.sanctum/logs/r2d2-audit.jsonl` is the second stop. Each cycle carries a `cycle_id`; grep it to follow one run end to end.
- **[Troubleshooting](./troubleshooting/)** has the top issues with copy-paste fixes.
- **Bug reports**: [open an issue on Ogilthorp3/sanctum-cli](https://github.com/Ogilthorp3/sanctum-cli/issues/new/choose). The bug-report template asks for `sanctum doctor` + `sanctum self-test` output and a credentials-redacted checkbox. The maintainers read it.

That's the whole contract, and it's a small one: your haus will not pretend. A green it can't back up is a lie, and Sanctum would rather hand you the awkward truth — the way Tommy, the haus's Abyssinian force-ghost, files the dawn weather whether or not the news is good. Fix the one red thing, and pour yourself more tea. You've earned the quiet that follows.
