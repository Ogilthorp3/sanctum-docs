## The canonical install path

Sanctum's public install path is **the Homebrew tap** at `Ogilthorp3/homebrew-sanctum`. The tap installs the `sanctum-cli` Python application, which orchestrates the rest — AI setup, network pairing, cloud backup, and a restore canary.

<Steps>

1. **Install Homebrew** if you don't already have it.

   ```bash
   /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
   ```

   Homebrew installs into `/opt/homebrew/` and asks once for your administrator password — that prompt is Apple's installer creating directories under `/opt/`, not Homebrew. When it finishes, `brew --version` prints something like `Homebrew 5.x.x`.

   <Aside type="tip">
   On a brand-new Mac, the first `brew install` may also offer Apple's Command Line Tools. Let it — a one-time macOS thing.
   </Aside>

2. **Install `sanctum-cli` via the Homebrew tap.**

   ```bash
   brew install ogilthorp3/sanctum/sanctum-cli
   ```

   This pulls in Python 3.12 and `restic` if you lack them (`restic` is the backup engine), creates a private virtual environment under Homebrew's `libexec`, fetches `sanctum-cli` v0.14.0 and its ~40 runtime Python dependencies from PyPI, and symlinks the `sanctum` command into `/opt/homebrew/bin/sanctum`.

   Confirm:

   ```bash
   sanctum --help
   ```

   You should see a help screen. The eight commands a new operator meets are `status`, `doctor`, `onboard`, `backup`, `cloud`, `chat`, `agent`, and `config`; the rest wait until you need them. `--help` is the authoritative list.

3. **Run the one-shot onboarding flow.**

   ```bash
   sanctum onboard --recipe family
   ```

   Onboarding is a guided arc with named chapters — **Welcome → Your AI → Your Network → Your Data → You're Alive** — a step counter, and a green check per step that lights only on genuine configuration or verification. A recap card closes it out.

   - **Your AI** connects **Claude** (a Max or Pro subscription, free through the local proxy by default, or an Anthropic API key) and **Gemini** (a Google AI key). Credentials go to the macOS Keychain. Skippable; the local `mlx_local` seat is always the offline fallback.
   - **Your Network** auto-detects your Bell hub, Firewalla, and Orbi and walks guided pairing. Fail-closed: a wrong password pairs nothing rather than half-pairing. Skippable too.
   - **Your Data** is what the `family` recipe was built for: a curated ~5 GB backup set, a pre-flight size check against R2's free tier, the backup itself, and a round-trip restore of `~/.zshrc` as a canary. That round-trip is the proof, not a rumour.

   When it finishes, you'll see a green panel: **"Your Sanctum is alive, &lt;your name&gt;."** Afterward, manage gear with `sanctum net hub|firewalla|orbi` and chat via `sanctum chat`.

   <Aside type="note">
   Other available recipes:
   - `operator` — for setting up a hub Mac Mini with the full sanctum stack (broader backup scope, no Photos auto-exclude)
   - Hub operator installs also offer the **service principal** gate (`sanctum service-user install`) so proxyd / Force Flow / Memory Vault run as user `sanctum` — see [Service Principal](/architecture/service-user/).
   - `code` — for a developer machine (Documents, dotfiles, ssh keys, plus `~/Projects`)
   - Or pass a path to a JSON file with custom paths.
   </Aside>

4. **Verify the install.**

   ```bash
   sanctum status        # one-line health snapshot
   sanctum doctor        # full diagnostic
   ```

   `status` prints a single line ending in green text. `doctor` runs deeper checks: the `com.sanctum.*` LaunchAgents, the AI providers (Claude, Gemini, the local MLX seat), and the restic backup repos — a real `restic check` on each. One OK line when healthy, `--full` for every row. Everything green is the goal.

</Steps>

## What you just got

| What | Where | How long it lasts |
|---|---|---|
| Daily backups (verified) | `com.sanctum.backup` LaunchAgent, 04:00 | Forever, automatic |
| Restore canary (proves round-trip works) | `com.sanctum.backup-canary` LaunchAgent, weekly (Sun 06:00) | Forever, automatic |
| Health snapshot command | `sanctum status` | On-demand |
| Deep diagnostic | `sanctum doctor` | On-demand |
| Local agent chat | `sanctum chat` | On-demand |
| Audit log of every action | `~/.sanctum/logs/` with bounded rotation | Rolls at 10 MB per file |
| Credentials in macOS Keychain | `security find-generic-password -a sanctum-backup -s sanctum-backup-key` | Until you rotate them |

No phone-home. Nothing leaves your Mac unless you configured a cloud backup target — encrypted with a key only you control.

## When something goes sideways

Most install runs work first time. The ones that don't usually hit one of these.

### "Your Command Line Tools are too outdated"

`brew install` checks for Xcode's Command Line Tools and refuses to build dependencies if they're missing or stale.

```bash
# Check what's installed
xcode-select -p
pkgutil --pkg-info=com.apple.pkg.CLTools_Executables

# Install or update
sudo xcode-select --install
```

If the install dialog doesn't appear, check System Settings → Software Update; Apple sometimes routes CLT updates through there.

### "Cloudflare R2 setup failed"

The R2 wizard opens browser tabs for the steps that need your input — account, API token, bucket. If a tab didn't open or you cancelled partway, re-run it:

```bash
sanctum cloud setup --backend r2
```

Plain `sanctum cloud setup` already defaults to R2. The wizard is idempotent — it picks up where you left off. If R2 is slow to provision, wait a few minutes and try `sanctum doctor` again.

### "Permission denied (publickey)"

This shows up if you ran `sanctum onboard` from a different Mac account, or with `sudo` (don't). Sanctum stores credentials in your user-level Keychain — run it as your normal user.

### "The brew tap failed to clone"

If `brew install ogilthorp3/sanctum/sanctum-cli` fails to clone (Git LFS or a cloning error), your global Git hooks may be blocking it. Check:

```bash
git config --global core.hookspath
```

A custom path there means those hooks need to soft-fail when their tools aren't found — see [`sanctum-runtime` post-checkout hook](https://github.com/Ogilthorp3/sanctum-runtime) for the canonical pattern.

### "Permissions prompts every time I run `sanctum`"

If you keep seeing macOS permission dialogs ("node would like to access X"), the canonical fix lives in [`runbooks/node-tcc-stop-the-prompts.md`](https://github.com/Ogilthorp3/sanctum-runtime/blob/main/docs/doctrine/runbooks/node-tcc-stop-the-prompts.md). Short version: grant Full Disk Access once to the pinned Homebrew node binary at `/opt/homebrew/Cellar/node/<version>/bin/node` (Cmd+Shift+G in the FDA pane to paste the path). FDA is a TCC superset, so that single grant silences every `SystemPolicy*` prompt across the sanctum node services. (It does not cover Automation or Accessibility — separate one-time grants, both in the runbook.)

## Appendix — Operator-grade install (running from source)

Running Sanctum from the source tree rather than the published binary uses a separate flow that installs the full audit-wall toolchain and the checked-in renderers.

<Aside type="tip">
You almost certainly do not want this if you're just trying Sanctum out — the brew path above is the whole beta-tester experience. This appendix is for people who plan to edit the renderer itself.
</Aside>

The legacy `sanctumctl` operator CLI drives the daily audit-wall and the release gate (`tools/sanctum-release.sh`), not new users. If you're maintaining a fork or building from a tag:

```bash
# From inside the checked-in workspace
python3 tools/sanctumctl.py bootstrap --write   # writes the ~/.sanctum scaffold
python3 tools/sanctumctl.py doctor              # runs the audited verification wall
```

That writes the `~/.sanctum` scaffold (annotated `instance.yaml.example` plus a node identity file) and runs the audited verification wall; `bootstrap` without `--write` previews first. The renderer just stopped trusting you to type it all by hand.
