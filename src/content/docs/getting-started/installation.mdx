## The canonical install path

Sanctum ships through the **Homebrew tap** at `Ogilthorp3/homebrew-sanctum`, installing the `sanctum-cli` Python package that orchestrates AI keys, network pairing, cloud backup, and a restore canary.

<Steps>

1. **Install Homebrew** if missing.

   ```bash
   /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
   ```

   Homebrew installs under `/opt/homebrew/` and asks once for your administrator password (Apple creating `/opt/` directories, not Homebrew getting nosy). Confirm with `brew --version` (`Homebrew 5.x.x`).

   <Aside type="tip">
   A brand-new Mac may prompt for Apple's Command Line Tools on first install. Let Apple have its moment — one-time macOS tax.
   </Aside>

2. **Install `sanctum-cli` from the tap.**

   ```bash
   brew install ogilthorp3/sanctum/sanctum-cli
   ```

   This installs Python 3.12 and `restic` if missing, builds a private venv under Homebrew's `libexec`, installs `sanctum-cli` and its 66 SHA-256-verified dependencies offline (`PIP_NO_INDEX=1`), and symlinks `/opt/homebrew/bin/sanctum`. (Alternatively, `curl -fsSL https://sanctum.run/install.sh | bash` automates Steps 1–2 plus the signed Node.js Foundation `.pkg`.)

   Confirm:

   ```bash
   sanctum --help
   ```

   Your first eight verbs are `status`, `doctor`, `onboard`, `backup`, `cloud`, `chat`, `agent`, and `config`; the rest stay out of your way until needed.

3. **Run one-shot onboarding.**

   ```bash
   sanctum onboard --recipe family
   ```

   Onboarding walks five chapters — **Welcome → Your AI → Your Network → Your Data → You're Alive** — lighting green checks only on verified steps:

   - **Your AI** stores **Claude** and **Gemini** credentials in macOS Keychain. Skip both if you only want the local Dragon.
   - **Your Network** probes for a Bell hub, Firewalla, and Orbi; skip it on a friend's Mac.
   - **Your Data** builds the `family` recipe (~5 GB), checks R2's free tier, backs up, and restores `~/.zshrc` as a canary. Proof, not rumour.

   At the finish, a green panel prints **"Your Sanctum is alive, &lt;your name&gt;."** Install the local Dragon from [Quick Start](./quick-start/). `sanctum chat` targets the operator council and bows out on a fresh Mac; the studio bundle seats your own council on the Dragon.

   <Aside type="note">
   Other recipes: `operator` (full hub backup scope, plus the optional `sanctum service-user install` gate — see [Service Principal](/architecture/service-user/)), `code` (adds `~/Projects`), or a custom JSON path list.
   </Aside>

4. **Verify the install.**

   ```bash
   sanctum status        # one-line health snapshot
   sanctum doctor        # full diagnostic
   ```

   `status` prints a single green line. `doctor` audits the `haus.sanctum.*` LaunchAgents, AI providers, and runs a real `restic check` on every backup repo (`--full` for every row). All green is the exit ticket.

</Steps>

## What you just got

| What | Where | How long it lasts |
|---|---|---|
| Daily backups (verified) | `haus.sanctum.backup` LaunchAgent, 04:00 | Forever, automatic |
| Restore canary (proves round-trip works) | `haus.sanctum.backup-canary` LaunchAgent, weekly (Sun 06:00) | Forever, automatic |
| Health snapshot command | `sanctum status` | On-demand |
| Deep diagnostic | `sanctum doctor` | On-demand |
| Local Dragon chat | the Dragon folder, or `./yoda.sh` in the studio bundle | On-demand |
| Audit log of every action | `~/.sanctum/logs/` with bounded rotation | Rolls at 10 MB per file |
| Credentials in macOS Keychain | `security find-generic-password -a sanctum-backup -s sanctum-backup-key` | Until you rotate them |

No phone-home. Nothing leaves your Mac unless you configured a cloud backup target — encrypted with a key only you control.

## When something goes sideways

Most install runs work first time. The ones that don't usually hit one of these.

### "Your Command Line Tools are too outdated"

`brew install` checks for Xcode's Command Line Tools and refuses to build dependencies if they're missing or stale.

```bash
# Check what's installed
xcode-select -p
pkgutil --pkg-info=com.apple.pkg.CLTools_Executables

# Install or update
sudo xcode-select --install
```

If the install dialog doesn't appear, check System Settings → Software Update; Apple sometimes routes CLT updates through there.

### "Cloudflare R2 setup failed"

The R2 wizard opens browser tabs for the steps that need your input — account, API token, bucket. If a tab didn't open or you cancelled partway, re-run it:

```bash
sanctum cloud setup --backend r2
```

Plain `sanctum cloud setup` already defaults to R2. The wizard is idempotent — it picks up where you left off. If R2 is slow to provision, wait a few minutes and try `sanctum doctor` again.

### "Permission denied (publickey)"

This shows up if you ran `sanctum onboard` from a different Mac account, or with `sudo` (don't). Sanctum stores credentials in your user-level Keychain — run it as your normal user.

### "The brew tap failed to clone"

If `brew install ogilthorp3/sanctum/sanctum-cli` fails to clone (Git LFS or a cloning error), your global Git hooks may be blocking it. Check:

```bash
git config --global core.hookspath
```

A custom path there means those hooks need to soft-fail when their tools aren't found — see `sanctum-runtime` post-checkout hook for the canonical pattern.

### "Permissions prompts every time I run `sanctum`"

If you keep seeing macOS permission dialogs ("node would like to access X"), install the signed Node.js Foundation `.pkg` at `/usr/local/bin/node` (which `sanctum.run/install.sh` verifies and installs for you — unlike Homebrew's versioned Cellar path, `/usr/local/bin/node` never moves across upgrades). On a full Sanctum 1.0 hub, protected Apple stores route through the notarized [SanctumBridge](/architecture/sanctum-bridge/) ("One Door"), so your shell and regular Node processes stay FDA-clean — see [TCC Identity Anchors](/architecture/tcc-identity-anchors/).

## Appendix — Operator-grade install (running from source)

Running Sanctum from the source tree rather than the published binary uses a separate flow that installs the full audit-wall toolchain and the checked-in renderers.

<Aside type="tip">
You almost certainly do not want this if you're just trying Sanctum out — the brew path above is the whole beta-tester experience. This appendix is for people who plan to edit the renderer itself.
</Aside>

The legacy `sanctumctl` operator CLI drives the daily audit-wall and the release gate (`tools/sanctum-release.sh`), not new users. If you're maintaining a fork or building from a tag:

```bash
# From inside the checked-in workspace
python3 tools/sanctumctl.py bootstrap --write   # writes the ~/.sanctum scaffold
python3 tools/sanctumctl.py doctor              # runs the audited verification wall
```

That writes the `~/.sanctum` scaffold (annotated `instance.yaml.example` plus a node identity file) and runs the audited verification wall; `bootstrap` without `--write` previews first. The renderer just stopped trusting you to type it all by hand.
