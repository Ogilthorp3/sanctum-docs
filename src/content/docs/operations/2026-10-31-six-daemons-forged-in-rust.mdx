Six quiet daemons on `manoir` had stopped evolving months ago. Under [Language Maturity](/architecture/language-maturity/), Python and Node stop paying rent there and start charging interest. So we read every line first. Auditing those six listeners before porting them to `sanctum-rs` exposed three live boundary flaws, plus a silent `launchd` duel leaking token prefixes every ten seconds.

## What was still running in interpreted runtimes

Memory and CPU told the first half of the story. Before cutover, `ps` on `manoir` showed six steady-state daemons burning `151 MB` of resident RAM and over thirty minutes of cumulative CPU on busy-polling loops and repeated interpreter startups:

## Four Rust crates, built the Apple way

Rather than redesigning any wire contract, we ported all six units into four focused crates in `sanctum-rs` (`bb52ca4`) with `100%` HTTP, SQLite WAL, and CLI parity:

1. **`services/sanctum-airlock` (`sanctum-ha-gateway` + `sanctum-dench`).** `sanctum-ha-gateway` canonicalizes every incoming URI — rejecting `%2e`, `%25`, `%2f`, `%5c`, nul bytes, backslashes, double slashes, and `..` segments before checking the method-scoped allowlist — validates bearer tokens via length-hiding SHA-256 `subtle::ConstantTimeEq`, holds `HA_TOKEN` in `zeroize::Zeroizing<String>`, logs only an 8-hex-char SHA-256 fingerprint, and writes `0600` structured audit entries. `sanctum-dench` links directly against Apple's `<launch.h>` `launch_activate_socket("Listeners", ...)` FFI so `launchd` (`PID 1`) binds `:80` and hands the descriptor to an unprivileged `UserName=sanctum` process, proxying HTTP and RFC 6455 WebSockets over `hyper 1.x` `on_upgrade` with zero raw header concatenation.
2. **`services/sanctum-msg-bus` (`sanctum-msg-bus`).** Preserves the exact SQLite WAL `queue.db` schema and `/enqueue`, `/msg/{id}`, and `/healthz` routes on `127.0.0.1:4076`, but replaces Python's `4 Hz` polling loop with `tokio::sync::Notify` (`0.0%` idle CPU) and passes iMessage text and buddy handles as positional `on run argv` parameters to `/usr/bin/osascript` so untrusted text never touches AppleScript syntax.
3. **`services/sanctum-chi` (`sanctum-chi`).** Serves `/chi` and `/health` on `127.0.0.1:7777` while preserving all five Jedi Council capacity invariants (`--self-test` verified), and folds the root `fseventsd` balloon sentinel into `sanctum-chi fseventsd` using XNU `proc_pid_rusage` (`RUSAGE_INFO_V4` `ri_phys_footprint`) plus existing `NOPASSWD` `footprint`/`pkill` rules from an unprivileged `StartInterval=300` LaunchAgent.
4. **`services/sanctum-sub-proxy` (`sanctum-grok-proxy` + `sanctum-agy-proxy`).** Wraps OAuth credentials in `Zeroizing<String>` with single-flight atomic `0600` refresh and `499` client-hangup stream aborts on `:4200`, while serving `:6543/health` from memory in `418 µs` (`test-agy-proxy-health.sh` `3/3` pass) and reaping timed-out CLI trees via negative-PGID `SIGTERM -> 2s -> SIGKILL`.

## Two traps caught during live cutover

Hot-swapping the LaunchAgents on `manoir` exposed two real host seams. Unit tests never saw them:

- **The silent `launchd` duel on `:8199`.** The moment we booted out `gui/501/haus.sanctum.ha-gateway`, a stale duplicate `/Library/LaunchDaemons/haus.sanctum.ha-gateway.plist` (`system/` domain, `ThrottleInterval: 10`, `SuccessfulExit: false`) grabbed `10.10.10.1:8199`. Inspecting `~/.sanctum/logs/ha-gateway/launchagent.log` showed that whichever copy lost the boot race had been failing with `EADDRINUSE` and respawning every ten seconds — `8,640` failed Node startups per day, each printing the `HA_TOKEN` prefix. Retiring `ha-gateway.js` into an immediate `exit(0)` stub satisfied `SuccessfulExit: false` on the stale daemon immediately while `~/.sanctum/scripts/sanctum-seal-root-daemons.sh` removes the duplicate plist permanently alongside the `:80` `sanctum-dench` socket-activation cutover.
- **macOS Application Firewall (`socketfilterfw`) vs. ad-hoc Mach-O on `bridge100`.** Loopback (`lo0`) daemons answered on the first millisecond, but `curl http://10.10.10.1:8199/health` completed the TCP handshake and stalled. Checking `/usr/libexec/ApplicationFirewall/socketfilterfw` explained why: `Firewall is enabled (State = 1)` with `Automatically allow built-in/downloaded signed software ENABLED`. `/opt/homebrew/bin/node` sat on the firewall allowlist; an ad-hoc (`codesign -s -`) Mach-O binary on non-loopback `bridge100` did not. Re-signing all six binaries with our Apple `Developer ID Application` certificate and **Hardened Runtime** (`--options runtime`, `flags=0x10000(runtime)`) both cleared `socketfilterfw` cleanly and turned on XNU's kernel enforcement against `DYLD_*` injection, unsigned code pages, and `task_for_pid` attachment.
