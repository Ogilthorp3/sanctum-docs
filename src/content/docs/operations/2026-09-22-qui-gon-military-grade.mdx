## 1. Anatomy of the 413 Storm and the Zombie Session

The incident began on September 15 following the OpenClaw 2026.9.4 release. A legacy prewarm sentinel script (`devstral-prewarm-sentinel.sh`) attempted to clear cold model caches by launching a sacrificial turn under a static session key (`agent:quigon:explicit:devstral-prewarm`). Historically, this sentinel purged its session by deleting obsolete `.jsonl` files from disk. The script failed. Old files vanished, but state lingered.

However, OpenClaw migrated session state to SQLite (`openclaw-agent.sqlite`). Because the cleanup script deleted files that no longer held state, each failed prewarm turn accumulated in the SQLite event log. The database choked. Nobody noticed. By September 21, the zombie session had ballooned into 6,209 raw events across 852 failed turns.

Every subsequent invocation loaded the full transcript history into memory, creating an insurmountable 45,143-token prompt. Every turn failed. The prompt exploded:

```bash
# Inspection of openclaw-agent.sqlite on ubuntu@10.10.10.10
sqlite3 ~/.openclaw/agents/quigon/agent/openclaw-agent.sqlite \
  "SELECT count(*) FROM session_events WHERE session_key LIKE '%devstral-prewarm%';"
# Result: 6209 events
```

When sent to the local MLX server on port `:3301`, the engine triggered an immediate rejection:

```text
sanctum_mlx::server: prompt exceeds operational cap — returning HTTP 413
prompt_tokens=38784 effective_cap=32768 operational_cap=32768 model_max=131072
```

Because `council-canary` only dispatched small probes ("2+2", 544 tokens), it consistently received HTTP 200, concealing an 18-day structural outage pattern from human view. The probe lied. Green meant nothing.

## 2. Hardening Qui-Gon's Configuration Diet

Restoring Qui-Gon required a decisive prompt diet across three core layers:

1. **Session Purge & SQLite Reclaim**: We purged the zombie session using the native CLI command `openclaw sessions delete 'agent:quigon:explicit:devstral-prewarm' --agent quigon --yes` and executed a database vacuum, shrinking the event store from 6,275 down to 66 events.
2. **Skill Pruning & Tool Deny List**: In `~/.openclaw/openclaw.json`, Qui-Gon's loaded skills were trimmed from 15 down to 7 infrastructure essentials (`code-forge`, `dench-ops`, `house-pulse`, `memory-vault`, `reboot-check`, `service-doctor`, `tailnet-toolkit`). Twenty-five unrelated tool schemas (`jocasta__*`, `ha-green__*`, `firewalla__*`) were placed on a hard deny list.
3. **Role-Based Seat Migration & Context Capping**: OpenClaw had previously configured the code seat with an obsolete model-specific name (`council-devstral`) and a phantom `131072` context window, disabling automatic compaction. Per the Sanctum Seat Naming Doctrine, seats are named strictly for their role, never for transient vendor models. We migrated the model identifier to canonical `council-code`, corrected `contextWindow` to `32768` and `maxTokens` to `4096`, and enabled `midTurnPrecheck: { "enabled": true }` to catch token pressure before dispatches hit MLX.
4. **Workspace & Sandbox Deduplication**: Redundant sections in `workspace-quigon/IDENTITY.md` were stripped and `MEMORY.md` was compacted from 9.2 KB to 1 KB, and immediately synced to docker sandbox container `agent-quigon-3c00f2c3`.

A live verification turn confirmed Qui-Gon's prompt plummeted from 45k tokens to 12,000 tokens, answering with immediate 17.5-second latency. The fix held. Latency vanished. He answered in seconds.

## 3. Deploying the Council Serving Sentinel

The root diagnostic gap was that our monitors answered *"is this seat alive?"* instead of *"is this seat serving real traffic?"*. A green probe is not traffic. The dormant sentinel script `council-serving-sentinel.sh` had been authored after an earlier outage scar but was never wired into launchd.

We operationalized the monitor into production:

- **LaunchAgent Deployed**: Created and symlinked `haus.sanctum.council-serving-sentinel.plist` to `~/Library/LaunchAgents/` with a 300-second execution cadence.
- **Three Core Verdict Gates**: The sentinel inspects real request lines from `~/.sanctum/logs/mlx-coder.log`, alerting to Force Flow on port 4077 if rejection rates exceed 20%, p95 prompt sizes collapse week-over-week, or caller offered prompt size exceeds 70% of operational capacity.
- **Automated SQLite Hygiene**: Installed `openclaw-session-hygiene.service` and timer on the Linux VM at `04:30 ET` daily to prune unreferenced artifacts and vacuum SQLite databases.

Tommy confirmed the serving logs reporting green across both `council-code` and cathedral brain seats. R2-D2 certified all unit checks across the dual-homed fleet. The gates hold. Qui-Gon is back. Qui-Gon now stands fully restored, military-grade, and actively guarded against token bloat.
