Memory never lies on Apple Silicon. When [Qui-Gon](/agents/qui-gon/) surveyed the estate, one number stared back like an uninvited guest: PID 2176 had consumed 3.3 GB of RAM.

For a lightweight ModernBERT classifier tasked with sub-50ms routing instincts, 3,286 megabytes was unacceptable. The estate needed answers before a memory triage cycle intervened.

## 1. Dissecting the Ghost in the Metal Heap

Standard process tools like `ps` and `top` reported a modest virtual size. But running Darwin's native `footprint` tool revealed the true culprit:

```bash
footprint 2176
```

Out of 3,286 MB total process footprint, **3,206 MB lived inside `IOAccelerator (graphics)`**. 

The Python runtime itself accounted for less than 80 MB. The rest was Apple Silicon unified GPU memory pinned by MLX. Two structural factors created this balloon:

1. **Precision Doubling:** The daemon launched with default `float32` precision. Loading the 421M parameter ModernBERT backbone (`aac6fef/laya-mlx`) consumed 1.6 GB of raw weights instead of the designed 804 MB.
2. **Unbounded Metal Buffer Caching:** MLX compiles computation graphs for three separate decision heads (`choice`, `score`, `noul`). Without an explicit cache ceiling, intermediate allocation buffers remained pinned in GPU device pools across turn warmups.

## 2. The Military-Grade Trim

We applied three targeted engineering interventions directly to the live daemon and launch configuration:

```python
# Cap Metal buffer cache to 128 MB
mx.set_cache_limit(128 * 1024 * 1024)

# Load weights in native bfloat16
AGENT = laya.load(MODEL_ID, dtype="bfloat16", compile=True)

# Flush graph tracing allocations post-warmup
AGENT.predict("system boot warmup", _dummy_schema)
mx.clear_cache()
```

In addition, we wired real-time Metal telemetry into `GET /health`, exposing `metal_active_mb`, `metal_cache_mb`, and `metal_peak_mb` so monitoring tools can verify memory bounds without spawning external diagnostics.

## 4. The Path to Native Rust

With 2.4 GB reclaimed, the Python MLX daemon now operates comfortably within estate limits. But the long-term destination remains `sanctum-rs`. 

By hosting ModernBERT directly inside a pure Rust service via vendored `mlx-rs` and HuggingFace `tokenizers`, the remaining 80 MB of Python runtime overhead drops away, enabling sub-20ms warm latency and strict zero-allocation boundaries.
