## 1. System Load & Post-Upgrade Indexing Triage

Upon host boot, macOS 27 initiated comprehensive migration passes across CoreSpotlight, Metadata, Photos/MediaAnalysis, and Mail:
- `hybridsearchd`, `corespotlightd`, `CGPDFService`, and `mediaanalysisd` consumed heavy background cycles.
- `Mail.app` ran `/System/Applications/Mail.app/Contents/MacOS/Mail -MailLibraryUpgradeOnly YES` against `/Users/bert/Library/Mail/V10/MailData/Envelope Index`.
- In addition, a recursive `grep` across the runner workspace had pegged one core at 100%.

Once the runaway search process was terminated and memory pressure subsided, host load plummeted from an initial peak of **151.02** down to **11.37**, restoring normal CPU scheduling and preventing starvation of timing-sensitive canaries.

## 3. SharePoint Bridge LaunchDaemon & Directory Permissions

Cloudflare Tunnel logs reported HTTP 502 errors when routing `https://bridge.nepveu.name` to origin `http://localhost:8443`.

Investigation revealed that system LaunchDaemon `/Library/LaunchDaemons/name.nepveu.sanctum-bridge.plist` (running as user `bert`) had failed to spawn with exit code 78 (`EX_CONFIG`):
1. **Directory Traversal Restriction**: Following the macOS upgrade, `/var/log/sanctum` was recreated with permissions `drwxr--r-- root:wheel`. Non-root processes could not traverse the directory to open `bridge.out.log` and `bridge.err.log`.
2. **Audit Log Failure**: The underlying service failed with `PermissionError: [Errno 13] Permission denied: '/var/log/sanctum/audit.jsonl'`.

Bert restored proper ownership and group permissions:
```bash
sudo chown -R root:sanctum /var/log/sanctum
sudo chmod 775 /var/log/sanctum
```
Launchd immediately spawned `name.nepveu.sanctum-bridge` on port 8443. The public bridge endpoint responded with `HTTP 200` (`ok v0.1.0 modules: m365, sharepoint`), and `sanctum-bridge-canary` successfully completed its document version upload (version 23 verified).

## 4. Provider Key Synchronization & Local Route Alignment

The `sanctum doctor` CLI command reported failures on `gemini` and `mlx_local`.

### Gemini API Key Rotation
The Keychain entry `google-ai-api-key` contained an expired key that failed with `400 INVALID_ARGUMENT`. Bert validated the live secret at `~/.sanctum/secrets/gemini-api-key` against Google's API (`200 OK`) and updated the macOS Keychain in-place:
```bash
KEY=$(tr -d '[:space:]' < ~/.sanctum/secrets/gemini-api-key)
security add-generic-password -U -a sanctum -s google-ai-api-key -w "$KEY"
```

### MLX Local Route Alignment
`sanctum-cli` had defaulted to legacy port 8900 for `mlx_local`. Bert configured `~/.sanctum/instance.yaml` under `cli.providers`:
```yaml
  providers:
    claude:
      via: proxy
      endpoint: http://127.0.0.1:3456
    mlx_local:
      endpoint: http://127.0.0.1:8055
      model: council-secure
```
Probing `sanctum-server` on `127.0.0.1:8055` confirmed `HealthSnapshot(ok=True, latency_ms=1)`.

### Headless SSH Automation
To eliminate passphrase prompts during unattended scripts, Bert updated `~/.sanctum/ssh/config` for `openclaw`, `10.10.10.10`, and `yoda` to place `~/.ssh/sanctum_automation_ed25519` first with `IdentityAgent none`. The configuration was committed and pushed upstream to `sanctum-config` (`1b8dc40`).
