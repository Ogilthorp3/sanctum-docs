Sanctum enforces a strict subscription-first and local $0 doctrine. Until now, agent decision-making lived at two extremes: brittle keyword regex matching or heavy frontier generative models. The deployment of `laya-mlx` bridges this gap, establishing a dedicated, zero-cost System 1 decision plane.

## Architecture

`haus.sanctum.laya` runs as a persistent background daemon on `127.0.0.1:1989`. It hosts the ModernBERT-large backbone (`aac6fef/laya-mlx`, ~421M parameters, ~803 MB FP16 safetensors) directly in Apple Silicon unified memory via MLX.

```
[User Prompt / Telemetry]
        │
        ▼
[~/.sanctum/lib/laya.py] ──(HTTP POST <15ms)──► [haus.sanctum.laya :1989]
        │                                                │
        ▼ (fail-soft fallback)                           ▼
[score_prompt() / Heuristics]                   [MLX FP16 Decision Head]
                                                         │
                                                         ▼
                                                Typed Outputs:
                                                - Choice (Route)
                                                - Score (Salience)
                                                - Noul (Boolean)
```

## Service Contract

- **Endpoint**: `http://127.0.0.1:1989`
  - `GET /_health`: Health, model name, uptime, request counter.
  - `POST /predict`: Input state string + typed question schema (`choice`, `score`, `noul`).
- **Resident Footprint**: ~28 MB process RSS, ~803 MB Metal buffer.
- **Qui-Gon Triage Level**: P1.5 (Permanent daemon, exempt from P2/P3 eviction).
- **Latency**: 11ms–70ms typical inference on Apple Silicon.

## Consumer Integrations

### 1. `sanctum-code` Routing & Diagnostics
`sanctum-code` queries `:1989` on every auto-route task. If Laya returns a valid route (`feature`, `ops`, `quick`, `review`, `hard`), it applies the typed decision and calibrated confidence. If the daemon is stopped, it transparently falls back to heuristic regex scoring.
Health status is surfaced directly via `sanctum-code doctor`.

### 2. Thalamus Global Workspace (`thalamusd.py` on `:1988`)
Thalamus arbitrates the global broadcast workspace for Sanctum agents. When agents post events without an explicit salience score, Thalamus automatically invokes Laya's semantic salience scoring (`score_salience()`), dynamically weighting urgent system events vs routine heartbeats based on text semantics. Thalamus also provides a dedicated `POST /salience` endpoint for real-time salience queries.

### 3. Sentinel Anomaly Triage (`sharepoint-bridge-sentinel.py`)
Sanctum sentinels monitor critical paths like the SharePoint / M365 authenticated bridge. Before escalating consecutive failures to Force Flow CRITICAL pages, `sharepoint-bridge-sentinel.py` queries Laya's `triage_incident()`. If diagnosed as a transient network timeout rather than an origin crash or auth failure, operator pager alerts are suppressed during temporary ISP jitter while maintaining immediate alerting on hard failures.

### 4. Sanctum CRM & Jocasta Privacy Firewall (`sanctum_crm/lib.py`)
In partner and work sessions (`CRM_SESSION=work`), Sanctum enforces strict privacy firewalls. Any communication draft, persona synthesis, or incoming text is passed through Laya's semantic privacy filter (`filter_privacy()`). If classified as `private_family` with $\ge 60\%$ probability, the operation immediately fails closed (`PermissionError`), protecting personal family communications from crossing into professional workspaces.
