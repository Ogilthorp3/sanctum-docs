## Why fifty downloads meant zero strangers

Fifty downloads with zero bug reports looked flattering. Then we checked the logs. Cross-checking GitHub Actions runs, Cloudflare edge path analytics, and `hive.sanctum.run` broke the illusion in five minutes:

- **CI inflated the headline.** Every `Test Formula` and `Build Homebrew Bottles` workflow in `homebrew-sanctum` pulled the release tarball on macOS runners, padding the counter on every version bump.
- **Our own fleet padded the rest.** Three Founder Apple Silicon Macs upgrading from `v1.0.0` through `v1.0.7` plus automated `.whl` scrapers filled out the count, while every `curl /install.sh` hit over fourteen days (`37/37`) came from Canada.
- **Zero strangers had joined.** Exactly three Founder nodes (`Seed #0`) and zero external Hive nodes had checked in, which explained the silence cleanly: nobody outside the walls had hit a bug because our counter had mostly been counting us.

Blind guesses stop here. We built a **Zero-PII Install Completion Funnel** across three layers and updated [Tommy's privacy ledger](/operations/privacy/) so code and docs stay matched to the letter:

1. **Cloudflare Worker (`hive.sanctum.run`):** Added an `install_funnel` D1 aggregate table and `POST /install-event` storing only `(date, step, cli_version, os_major, country, count)` — zero IPs, zero user agents, zero device IDs — proven by `3/3` Worker unit tests including negative checks against IP storage and bad payloads.
2. **Installer (`sanctum.run/install.sh`):** Sends non-blocking milestone counts (`bootstrap_started`, `clt_missing`, `cli_installed`, `bootstrap_completed`), skips automatically in CI or owner smoke runs, and honors `SANCTUM_NO_TELEMETRY=1` and `DO_NOT_TRACK=1`.
3. **Collector and Command Center (`beta-pulse-collect.py` v3 + `BetaPulseView.tsx`):** Separated Homebrew bottles cleanly from Rust suite tarballs, subtracted estimated CI and founder traffic into an explicit **Install Truth Funnel** and **Noise Audit**, and verified the schema with `6/6` hermetic collector tests.

## The OpenSSH parser split we caught and locked down

One regression slipped through during SSH hardening. We owe it an honest note.

Adding `HostKeyAlgorithms ssh-mldsa44-ed25519,ssh-ed25519` to shared `ssh/config` worked under Homebrew OpenSSH `10.6p2`, yet broke Apple's stock `/usr/bin/ssh` (`10.5p1`) because OpenSSH validates `HostKeyAlgorithms` globally and Apple's build only knows the `@openssh.com` suffix. Background LaunchAgents invoking `/usr/bin/ssh` failed immediately until a sibling session caught the mismatch, removed the version-divergent line (`sanctum-config@f5c81b4`), and added dual-parser assertions to `tests/test-ssh-usekeychain.sh` (`7/7` passing across both `/usr/bin/ssh -G` and `/opt/homebrew/bin/ssh -G`). In the same closeout sweep, we triaged all eleven untracked `sanctum-config` files back to `0` drift across eight repos (`sanctum-config@e38dd77`) and updated `windu-doctor.py` to read `firewalla-bridge-token` directly and match Rust `sanctum-firewalla-bin` instead of legacy `firewalla-bridge.js` (`sanctum-config@4bfe4c7`, restoring `curfew_enforcement` and `device_quarantine` to `OK` with `36/36` security tests passing).
